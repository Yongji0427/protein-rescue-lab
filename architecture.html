Protein Rescue Lab
RESEARCH × ENGINEERING

Can a second mutation rescue a damaged protein?

An agent explores candidate substitutions using public features and budgeted historical measurements, then builds a traceable conclusion.

01 / RESEARCH WORKFLOW

From question to evidence

A second substitution is a candidate rescue—not a proven mechanism.

01

Define the task

Identify a damaging mutation and the legal candidate rescue substitutions.

02

Explore and predict

Inspect public features and observed results; record a hypothesis.

03

Query measurements

Commit candidates, predictions and rationale before feedback is revealed.

04

Evaluate evidence

Compare observed controls, revise the hypothesis and decide whether to continue or conclude.

03 / EVALUATOR

Evaluator

Validates requests, enforces the budget and maintains task state.

← Observed measurements and remaining budget return through the toolbox to the agent.

Agent-visible information

Public candidate features and measurements already revealed to the task.

Evaluator-held information

Unqueried historical labels and persistent task records; eligible results are revealed after valid queries.

Restricted analysis

The Python tool runs in a restricted macOS subprocess using visible task data.

Current toolbox configuration: up to 32 combination labels, including 8 shared initial observations, and 1–4 candidates per new query. This is a retrospective research prototype, not a wet-lab experiment. The evaluator can access input labels; complete OS-level isolation is not claimed.
